# AREVÉ brand experience — review implementation

Design authority: supplied AREVE Brand Identity Package, Guidelines v7, Option 02 “The Modern Heirloom”. Uses the approved unmodified wordmarks, primary marks, icon and Arch pattern; exact ivory, charcoal, sand, walnut and botanical digital palette. Brass remains a physical finish. Playfair Display and Poppins are served locally with OFL notices and renamed subset font metadata; obsolete font dependencies were removed.

The home and World pages interpret the brand's heritage and gifting story. The packaging study is explicitly a concept, not product photography or an order customization. CSS perspective supplies six box faces and a separate lid. Rotation, colour and opening are explicit keyboard/touch actions; no WebGL dependency, animation loop, model downloads or external service. Reduced motion removes transitions, unsupported transforms have a static fallback, and all controls have accessible names and 44px targets.

Navigation uses a modal drawer with focus containment/restoration and scroll locking. Region/language controls use native keyboard/touch selectors with pending/error states. Brand assets bypass region middleware. Checkout indicators are decorative within the parent radio, avoiding nested interactive controls. Product prices use contrast-safe brand tokens.

Validation (25 November 2026): TypeScript, lint, 28 unit tests, optimized production build. Full desktop/mobile regression: 32/34 initially passed; the two failures found an inherited nested-radio defect. After its fix all 10 checkout regressions passed. All 10 brand/browser/accessibility tests also passed against the production build, including 320px layout, asset content types, keyboard navigation and reduced motion. Automated WCAG A/AA checks on home, World, menu, product, cart, address and payment reported no remaining violations in those checks.

Remaining dependencies: approved SKU images, product content and final legal/operational content. Browser test fixtures are not approved launch merchandise. This batch does not claim hosted provider or live-payment verification.

## Final MVP refinement

The account, order history, product gallery, basket, recovery and not-found states now share the same brand hierarchy. Mobile accounts expose the same overview/navigation as desktop; older orders are paginated. Shared dialogs have labelled controls, valid autofill semantics, scrollable narrow layouts and motion that preserves text contrast. Broken merchandise images have meaningful fallbacks; unused starter content is removed.

Navigation consumes the page layout's existing cart instead of issuing a duplicate read inside a Suspense boundary. Production traces showed complete successful mutation responses with stale client views; removing that redundant streamed boundary and using React action transitions eliminated the reproduced stall in 20 repeated account/cart recovery journeys. This symptom is consistent with the [upstream production rendering report](https://github.com/vercel/next.js/issues/87529); no framework migration or arbitrary timing delay was introduced. Payment callbacks use relative redirects to preserve the customer's browser origin. Customer reads no longer expand the full order history on every storefront page.

The pinned Next 15 build uses [optimized package imports](https://nextjs.org/docs/app/api-reference/config/next-config-js/optimizePackageImports) for Medusa UI/icons. This option is experimental and must remain covered by production builds and browser regressions. First-load JavaScript dropped from approximately 360KB to 198KB on the home page and to 106KB on policy pages. In a local Lighthouse run, homepage transfer fell from 548KiB to 390KiB and total blocking time from 50ms to 10ms; LCP was 0.8s and CLS 0. These are synthetic local measurements with review imagery, not field performance certification. Review noindex/robots rules intentionally lower the SEO score.

Final refinement verification: 31 storefront unit tests, TypeScript, lint and production build; 53 passing desktop/mobile browser journeys, with three deliberate skips (two large-catalogue cases require the separate 105-product fixture, and the duplicated mobile settings-console case is desktop-only). The large-catalogue behavior has earlier separate fixture evidence. Full axe checks cover the account editors/dialog, order history, product/options, basket, checkout, public policies and custom admin views. A separate 48-case audit across 320/375/768/1440px found no remaining axe violations, overflow or broken images on the sampled public routes. Automated checks supplement visual and keyboard review; they do not establish exhaustive accessibility compliance.

Product-page Lighthouse runs scored 90–96 performance, 100 accessibility and 100 best practices, with 0 CLS and 0–10ms blocking time. The explicit high-priority hero image resolves the request-priority finding. Simulated LCP varied between 2.8s and 3.6s; repeat the performance budget with approved merchandise imagery and hosted latency before release. SEO remains 66 because indexing is intentionally disabled in review.
